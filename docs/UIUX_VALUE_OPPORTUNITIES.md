# ScreenshotApp：使用者體驗與產品價值改善機會

分析日期：2026-10-29。分析基準：目前工作區的 v1.1.0 程式碼，Git HEAD 為 7729736；歷史畫面與驗收紀錄另標示版本及日期。

**最值得先開始的是 O01「情境化編輯工作區與一致的可操作介面」：讓使用者一眼知道正在操作什麼、下一步在哪裡，以及哪些設定會影響目前物件。** 這會改善截圖與開啟既有圖片之後共同使用的主流程。它的價值來自反覆使用時減少尋找、猜測與誤操作，以及更清楚的視覺層級，不能只視為換皮。

## 1. 產品／使用者摘要

### 1.1 產品承諾與目標使用者

**事實**：ScreenshotApp 是 Windows 11 x64 常駐工具，核心工作是「截圖 → 標註 → 複製或另存 PNG」。規格明確以經常製作技術簡報、操作手冊、缺陷回報與架構說明的個人軟體工程人員為主要使用者。它採本機離線、免帳號、不上傳、不自動保存螢幕內容的產品方向。[E01](#e01)

| 使用者／情境 | 要完成的工作 | 最有價值的改善 | 證據性質 |
|---|---|---|---|
| 軟體工程人員回報缺陷 | 指出錯誤位置、附簡短說明，再貼入溝通工具 | 快速找到工具、文字清楚、安全遮蔽、確認貼出正確版本 | 目標與情境為事實；改善效益為推論 |
| 操作手冊與簡報製作者 | 連續製作外觀一致的步驟圖 | 可重用樣式、編號、批次調整、減少重做 | 前兩種用途見規格；連續製作的頻率未量測 |
| 已熟悉快捷鍵的個人使用者 | 少打斷目前工作，快速完成一張圖 | 固定操作位置、保留快捷鍵、明確但不干擾的回饋 | 推論；沒有熟手占比資料 |
| 第一次接觸的使用者 | 找到已啟動的程式，完成第一張圖 | 首次導引、操作提示、可見的說明入口 | 初次啟動進系統匣為事實；流失程度未知 |
| QA、客服、教育訓練與企業內部團隊 | 分享可理解、可安心流通的畫面 | 遮蔽、樣式、可信任的發佈與相容性說明 | 相鄰市場推論，尚非經驗證的目標客群 |

**業務價值的定義**：此 Repository 未提供付費方案、客戶數、下載轉換或收入資料。本報告以首次成功率、日常採用、持續使用、成品溝通品質與推薦意願衡量價值；不把「可能有企業需求」寫成已有商機。

### 1.3 已有的價值應保留

1. **快速且專注**：不需要帳號或網路，沒有強迫管理圖片庫的負擔。歷史煙霧量測在單一 3456×2160、175% 顯示器上，快捷鍵到覆蓋層中位數 154 ms，600×400 選取完成到編輯器前景中位數 91 ms；不能推廣為所有設備的效能。[E18](#e18)
2. **可反悔的編輯**：標註獨立於原圖，裁切非破壞性；新增、修改、刪除、再製、重排編號等已有復原機制，不應再把「新增 Undo」列為機會。[E10](#e10)、[E11](#e11)
3. **資料保護與輸出一致性**：失敗時保留圖片；複製與另存共用合成與 PNG 編碼；來源檔案不會被預設覆寫。改善應讓保護更容易理解，而非撤掉它換取較少步驟。[E08](#e08)、[E09](#e09)、[E12](#e12)
4. **已有基本可操作性**：按鈕有圖示加文字、存取鍵與提示；顏色色塊有可存取名稱，設定中還有文字名稱；多處使用系統色彩，歷史紀錄有 Tab 巡覽。不能寫成「完全沒有 Accessibility」。[E03](#e03)、[E05](#e05)、[E18](#e18)

## 2. 主要 UI／UX 與系統性問題

### 2.1 情境與資訊層級不足，影響共同的編輯主流程

**事實**：主工具列共有 13 個操作：8 種工具、復原／重做、開啟／複製／另存。它們使用接近的視覺重量，雖已有分隔線，仍集中在同一個 WrapPanel。第二列同時保留顏色、線寬、字型、字級、編號值。程式依選取物件停用不適用欄位，但沒有用標題明示「正在修改選取物件」或「新增物件的預設值」。沒有選取時，顏色、線寬與字級變更還會寫回偏好設定。[E03](#e03)、[E04](#e04)、[E15](#e15)

**推論**：每次讀取屬性列都要先在心中判斷作用對象；新增功能會進一步增加掃視負擔。這是跨工具的共同問題，集中為 O01，不拆成「改工具列」「改字級」「改間距」數個小案。

**建議**：區分「工具」「目前物件／新增預設」「交付」三個區域，讓主要輸出操作固定可找；只呈現有關的屬性，並保持欄位的相對位置穩定。裁切提供可見的套用／取消；把既有右鍵功能補上可用鍵盤到達的入口。

![v1.1.0 歷史編輯器畫面：頂端工具與屬性列、底部狀態列](evidence/phase-07/release-phase3-cropped-fill.png)

此圖來自既有煙霧驗證，漸層是測試底圖，**不是產品的介面配色**。它能支持版面觀察，不能代表真實文件分布、使用者視力或所有 DPI 下的閱讀體驗。[E22](#e22)

### 2.2 回饋有提供，但狀態與「下一步能做什麼」連結不足

**事實**：成功訊息在六秒後消失。一般編輯變更會更新介面，但不立即清除前一次成功訊息；裁切提示也使用同一訊息位置。匯出中主要以停用命令處理；開圖解碼時控制器維持忙碌狀態。剪貼簿或存檔失敗有繁體中文原因與保留圖片說明，但錯誤框只有「確定」，沒有直接重試或改存入口。[E07](#e07)、[E08](#e08)、[E16](#e16)

**推論**：在成功後立即繼續修改，或背景編碼期間修改時，使用者未必能分辨「剛剛輸出的版本」與「現在看到的版本」。失敗可恢復，卻還要自己找到下一步；忙碌時忽略新要求也可能被感受成按鈕沒有反應。此問題跨開圖、複製、另存與切換文件，合併為 O03。

**資訊不足**：實際重複點擊、錯貼版本與放棄任務的比例，資訊不足，無法確認。不能把短暫阻塞等同於整個應用程式不穩定。

### 2.3 可讀性、視窗適應與輔助操作需要一套共同驗證標準

**事實**：編輯器最小尺寸為 720×420 DIP，工具列會換行；設定內容寬度固定為 460 DIP，視窗不可調整大小且沒有整體捲動容器。應用層沒有明確的介面字級階層；設定提示使用系統 GrayText。畫布取消預設焦點外框，控制點由自繪圖層提供，標示尺寸為 8 DIP；命中另有容差，不能把視覺尺寸直接視為點擊範圍。選取覆蓋層的鍵盤處理只有 Esc；標註沒有一般控制項般的鍵盤選取清單。[E03](#e03)、[E05](#e05)、[E14](#e14)、[E23](#e23)

**推論**：小工作區、較大的系統文字或輔助科技使用者，可能更難到達功能、確認焦點或精確調整位置。既有 Tab 巡覽驗證只代表可巡覽那些控制項，不能推導完整工作流程可用鍵盤完成。這些應納入 O01 的共同介面品質；精確框選替代操作則在 O09 評估，不另外建立一個重複的美化項目。

**資訊不足**：實際字級、各主題前景／背景對比、文字放大後是否截斷、Narrator 宣告、完整鍵盤流程與色覺差異體驗，資訊不足，無法確認。**沒有證據支持「全產品字太小」「所有面板低對比」或「所有控制項無法被輔助科技辨識」。**

### 2.4 成品的可讀性直接決定溝通價值

**事實**：一般文字以單一顏色繪製，沒有文字底色或外框，自動換行未提供；預設文字為 20 個圖片像素，與 UI 字級是兩個概念。顏色、線寬、字級會保存，字型不跨編輯視窗保存。步驟數字已依圓形底色選黑／白字，代表產品已有局部的可讀性處理。[E13](#e13)、[E15](#e15)

**推論**：同一種字色在亮、暗或複雜底圖上不一定都清楚；不同截圖解析度、文件縮放會改變成品的閱讀體驗。使用者在每張圖重調樣式，或到 PowerPoint 再加文字，都會削弱工具價值。O04 以成品品質與樣式重用為主，不與 O01 的應用介面字級混為一談。

### 2.5 首次發現與持續學習過度依賴外部文件

**事實**：正常啟動只進系統匣，雙擊圖示開啟設定，編輯器與系統匣沒有使用說明入口。重新編號、反轉箭頭等已實作能力位於特定右鍵選單；文字完成、裁切套用與工具存取鍵的資訊存在工具提示和使用說明中。[E02](#e02)、[E03](#e03)、[E06](#e06)、[E16](#e16)

**推論**：使用者可能覺得「功能沒有提供」，實際上只是找不到。O05 處理從啟動到學會的路徑；下載簽章、版本與更新信任另列 O10，因其受益情境及維護責任不同。

### 2.6 空間模型有一項值得追蹤的落差

**事實**：一般裁切後只顯示裁切範圍，但命中判定遍歷所有標註，指標限制仍以整張原圖為界。既有 findings 記錄灰色區可能選到或建立看不見的標註；目前相關原始碼仍與此描述一致。[E24](#e24)

**推論**：這會造成「我點的是空白，為什麼選到物件」的困惑，應以 O11 改善可見範圍與操作範圍的一致性。尚未在本次實機重現，發生率與嚴重度分布未知；不能把它描述成輸出一定錯誤。

### 2.7 美感偏好與可驗證問題分開處理

| 類型 | 本報告的判斷 | 驗證方式 |
|---|---|---|
| 可驗證：資訊層級 | 同等重量的多個操作、預設值與選取物件缺少明示，是已知介面結構 | 任務完成時間、首次點對比例、作用對象辨識 |
| 可驗證：可讀性／Accessibility | 需檢查字級、對比、文字放大、焦點與輔助科技；目前不能宣告不合格 | 實際呈現量測、鍵盤任務、Narrator 與不同需求使用者測試 |
| 可驗證：一致性 | 色彩選擇在設定中有可見名稱，在編輯器主要依色塊與提示；提交動作有情境差異 | 跨畫面任務的學習轉移、錯誤與求助次數 |
| 主觀美感偏好 | 偏好圓角、Fluent、無框按鈕、深色背景或不同圖示風格 | 同任務完成度下的偏好與專業感評分，不單獨作高排名理由 |

視覺品質包含閱讀秩序、選取狀態、對齊、留白與成品清楚程度，不等同於「改成某套流行風格」。原生 Windows 操作習慣本身也有價值。

## 3. 候選改善機會與評估方法

### 3.1 價值優先，成本分開

所有候選先按同一組十個面向評分，單項 1～5 分；5 代表對此產品情境的預期貢獻最大。**評分全部是分析推論，沒有把分數當成實測。**

| 面向 | 權重 | 本產品的判斷問題 |
|---|---:|---|
| User Value，使用者價值 | 15% | 是否更容易完成一張能使用、能交付的圖？ |
| Usability，易用性 | 12% | 是否容易找到、學會與正確操作？ |
| Visual Quality，視覺品質 | 10% | 介面或成品是否更清楚、一致、有專業感？ |
| Productivity，生產力 | 12% | 是否減少重複、切換與修正？ |
| Cognitive Load，認知負荷 | 10% | 是否減少猜測與記憶負擔？分數高代表降低更多 |
| Usage Impact，使用影響 | 12% | 是否涵蓋共同流程或反覆使用的情境？頻率尚待量測 |
| Business Value，業務價值 | 10% | 是否支持採用、留存、信任或團隊使用？ |
| Differentiation，差異化 | 6% | 是否強化本機、繁中、輕量工作流程的吸引力？沒有做競品市占比較 |
| Product Maturity，產品成熟度 | 7% | 是否補齊可信、完整、可恢復的產品體驗？ |
| Strategic Leverage，後續效益 | 6% | 是否讓既有能力及後續改善更容易發揮價值？ |

總分＝Σ（單項分數 ÷ 5 × 權重），滿分 100。成本與風險不進入分母，也不加減價值分。小數只用於核對計算；相近分數不代表實質差距。中／高成本是相對範圍與驗證負擔，沒有團隊產能資料，不能換算可靠工期。

### 3.3 主動評估後，不建議優先加入的東西

- **Dashboard、跨圖片搜尋／Filter／Sort／Group、Saved View**：目前沒有持久圖片庫或跨文件資料集。先加資料庫再做儀表板會改變產品定位；這些能力的需求證據不足。標註多選與群組需求由 O08 處理，輸出檔案整理由 O13 處理，不先做圖片管理平台。
- **預設自動儲存、截圖歷史、雲端分享與遙測**：與明確的隱私決策衝突。O07 的手動保存與 O20 的選用恢復須分開評估，不能把它們包成無條件的「成熟度必備」。
- **單純深色主題、圓角與動效改版**：屬偏好或品牌表現；先證明可讀性、對比與效率收益。若高對比實測發現障礙，則應直接提高改善優先度，不受「只是 UI」的折扣。
- **廣泛串接企業 SaaS**：現有剪貼簿與 PNG 已承接主要整合情境。沒有使用者證據前，不增加帳號、網路與授權管理負擔。

## 4. Top 5：依整體價值排序

### 第 1 名：O01 情境化編輯工作區與一致的可操作介面

- **現況與問題｜事實**：13 個頂端操作、常駐屬性列、以停用表示不適用；部分命令只能從情境右鍵選單找到；設定視窗與自繪畫布的尺寸、焦點與輔助操作仍缺完整實測。[E03](#e03)～[E05](#e05)、[E23](#e23)
- **建議改善**：建立工具／情境屬性／交付的層級；明示目前物件與新增預設；提供裁切套用／取消與可見的物件操作入口；統一字級、間距、焦點及小視窗規則，保留既有存取鍵和右鍵效率。
- **使用者／產品／業務價值｜推論**：降低第一次學習與每次操作的認知成本，讓既有能力更容易被使用；提高專業感及持續使用意願。這些改善同時服務新截圖與開啟圖片，不限單一新功能客群。
- **預期影響｜待驗證**：找工具與屬性的時間縮短、修改錯誤對象減少、小工作區仍能完成任務。以任務時間下降 25% 作為原型目標，不宣稱已達成。
- **實作成本與風險**：中。主要風險是熟手位置記憶被破壞、動態屬性使版面跳動、鍵盤焦點遺失，以及過度放大控制項壓縮畫布。應先用穩定區域與小範圍原型驗證，非全面改寫 UI。
- **Repository 證據**：EditorWindow.xaml 的操作分組與尺寸、SyncStyleControls 的停用規則、SettingsWindow.xaml 的固定版面、歷史畫面與 Tab 巡覽紀錄。
- **反方觀點**：對熟悉 Alt 存取鍵的人，現有原生 UI 可能已足夠快；改版可能只有新鮮感。若新手錯誤不降、熟手變慢，就縮減改動。缺乏目前任務基準，是此排名最大的限制。

### 第 2 名：O02 安全分享的實色遮蔽

- **現況與問題｜事實**：規格與已知限制明列沒有實色遮蔽、模糊或馬賽克。一般矩形主要畫外框；尺寸不超過兩倍線寬時才因幾何條件變實心，這不是有明確語意的遮蔽工具。[E13](#e13)、[E17](#e17)
- **建議改善**：提供名為「遮蔽」的不透明實色工具；在編輯時可調整與復原，輸出則把遮蔽正確合成至 PNG 與 DIB。輸出前讓使用者檢查遮蔽範圍，避免把粗框、半透明色或模糊誤當可靠遮蔽。
- **使用者／產品／業務價值｜推論**：缺陷回報與操作手冊可能包含姓名、帳號或內部資訊。能在同一個離線流程完成遮蔽，可減少切換工具，也強化「可安心分享」的產品吸引力。實際含敏感內容的任務占比未知。
- **預期影響｜待驗證**：減少為遮蔽轉去其他工具的任務、降低漏遮與重工；驗證重點是輸出範圍內的像素與各剪貼簿格式，不是只看畫面上有黑框。
- **實作成本與風險**：中高。風險包括邊緣漏出、層序與裁切交錯，以及未來可編輯文件仍含原圖。不能承諾自動找出全部敏感資訊，也不能把可編輯文件當成已安全去除原始資料的分享格式。
- **Repository 證據**：不實作清單、AnnotationPainter.PaintRectangle、同一繪製器與輸出器、剪貼簿雙格式測試。[E09](#e09)、[E12](#e12)、[E13](#e13)
- **反方觀點**：若主要用途只是公開技術畫面，遮蔽頻率可能低於 UI 摩擦；截掉敏感區也能解決部分情境。應先用真實任務確認切換成本。若目標使用者經常分享敏感畫面，O02 應超越 O01 成為第一優先。

### 第 3 名：O03 可信交付狀態與可恢復回饋

- **現況與問題｜事實**：資料模型已追蹤匯出版本，且測試確認匯出期間的修改仍屬未匯出；介面則用六秒成功訊息、停用命令及一般錯誤框。成功訊息不會因下一筆修改立即改成「目前版本尚未輸出」。[E08](#e08)、[E10](#e10)、[E19](#e19)
- **建議改善**：把目前版本狀態持續呈現；載入或匯出較久時顯示處理中；失敗提供「重試」「另存 PNG」或「選其他位置」。成功後可提供「開啟所在資料夾」與選用的「複製並返回工作」；返回不得強制關閉文件或自動貼到別的程式。
- **使用者／產品／業務價值｜推論**：使用者能回答「現在交付的是哪一版、成功了嗎、失敗後能做什麼」，降低重複操作與錯誤交付，提升可靠感。後續少步驟交付可建立在這個可理解狀態上。
- **預期影響｜待驗證**：版本辨識正確率提高、複製後重複點擊與求助下降、失敗後完成率提高。不能因顯示「已複製」就宣稱外部應用程式已成功接收。
- **實作成本與風險**：中。需要分清成功匯出的歷史版本、現在版本、目的地與外部剪貼簿變更。現有單一 ExportedVersion 不足以直接代表各目的地狀態；也應避免永遠顯示過時的「剪貼簿是最新」。
- **Repository 證據**：CopyImageAsync、SaveImageAsync、SetExporting、ShowMessage／UpdateMessage、AppController.OpenImage、DirtyTrackingTests、繁中錯誤文案。
- **反方觀點**：常見尺寸的輸出歷史量測很快，完整進度條可能增加干擾；既有錯誤已保留圖片且說明處理方式。應優先解決版本語意與失敗操作，只有超過合理延遲才顯示忙碌提示，不製造假的百分比。

### 第 4 名：O04 可讀且可重用的標註樣式

- **現況與問題｜事實**：文字沒有底色／描邊或自動換行；預設樣式只持久保存顏色、線寬、字級；字型不跨編輯視窗保存；沒有命名樣式組合。[E13](#e13)、[E15](#e15)
- **建議改善**：先提供少量可預覽的「一般說明／強調／步驟」樣式，允許完整樣式重用；文字可選不透明底色或描邊，並以文字框控制換行。保留圖片像素單位與原本的自由配色，不擅自改已存在的標註。
- **使用者／產品／業務價值｜推論**：讀者更快看懂重點，作者較少為每張圖調整；一組手冊或簡報有一致的字級與色彩，成品質感能直接展示產品價值。
- **預期影響｜待驗證**：在亮、暗、複雜底圖的標註閱讀辨識率提高；完成一組圖的樣式調整次數減少。評分應同時看圖片接收者，不只看作者是否喜歡配色。
- **實作成本與風險**：中高。自動換行改變文字範圍及命中，需驗證 IME、重新編輯、縮放與輸出一致性；預設太多會重新增加 O01 的認知負荷。可先驗證底色和樣式重用，再決定文字框投資。
- **Repository 證據**：TextLayout、TextAnnotation 繪製、AnnotationPainter 的編號黑白字選擇、AppSettings、StyleChoices、字型生命週期說明。
- **反方觀點**：粗字或底色可能遮住原圖，固定模板也可能讓簡單截圖變擁擠。閱讀改善必須由任務結果支持；偏好圓角標籤或特定品牌色，本身不是普遍使用者價值。

### 第 5 名：O05 首次成功與隨手可查的操作導引

- **現況與問題｜事實**：正常首次啟動沒有主視窗，工具提示及外部文件承擔教學；系統匣沒有 Help。再次啟動通常帶出設定，而不是開始截圖。[E02](#e02)、[E06](#e06)
- **建議改善**：首次明確說明「已在系統匣待命、目前快捷鍵、如何開始」，提供可略過且之後可重新開啟的三步導引；編輯器提供精簡操作說明與快捷鍵表。學習入口靠近動作，熟手之後維持安靜常駐。
- **使用者／產品／業務價值｜推論**：減少「啟動沒反應」及功能找不到的感受，提高第一次完成與再次使用的可能性；讓再製、編號重排等既有能力真正被發現。
- **預期影響｜待驗證**：首次完成截圖、標註並貼出的比例提高，求助及反覆啟動次數下降。尚無下載漏斗資料，不能承諾轉換率提升幅度。
- **實作成本與風險**：中。首次導引會改變既有啟動契約，需先修改規格；不能在每次登入強制彈出，也不能只靠可能被抑制的系統通知。
- **Repository 證據**：AppController.Start、TrayService、USER_GUIDE 的啟動及快捷鍵章節、Strings.resx 的工具提示；既有設定檔未包含導引狀態。
- **反方觀點**：主要使用者是技術人員，可能偏好完全沒有導引。應以新手任務測試決定是否只需一個輕量提示與 Help，而不是完整導覽精靈。

## 5. Top 1 最終推薦

**先以 O01 的小範圍原型驗證「更容易理解、找得到、操作正確」的價值，再投入完整介面調整。**

優先原因是它位於所有截圖與圖片標註的共同路徑，且現有工具、文字資源、情境判斷與可逆操作已具備，改善能讓既有投資被使用者看見。選它不是因為容易做：跨版面、鍵盤與 DPI 的驗證負擔並不小，而熟手習慣也是必須保護的產品資產。

主要受益者為第一次製作說明圖的人、偶爾使用但記不住操作的人，以及每天反覆切換工具與屬性的文件作者；小工作區、較大文字與鍵盤操作需求的使用者也應列入設計驗證。

核心價值可以用一句使用者語言描述：**「我知道目前改的是哪個東西，也看得見完成這一步的方式。」**

排序仍有條件：若訪談顯示敏感內容遮蔽是大部分任務的必要步驟，先做 O02；若現有使用者大多熟悉所有操作且 O01 原型無改善，改投 O03 或 O04。資訊不足時應降低對排序的信心，不應假造 ROI。

## 6. 建議 MVP 與不包含範圍

### 6.1 MVP：完成四種常見編輯任務的介面改善

驗證任務為「新增箭頭／文字」「只改選取標註的樣式」「套用及取消裁切」「找到複製與另存」。以下是建議範圍，尚未修改規格或實作。

| MVP 項目 | 使用者看得到的改變 | 驗收重點 |
|---|---|---|
| M1 穩定的工作區層級 | 工具、目前操作屬性、交付操作分區；複製／另存固定可找，八種工具都保留 | 小視窗不靠猜測找到主操作；工具切換不讓主操作跳位置 |
| M2 明確的作用對象 | 顯示「正在編輯：箭頭」或「新增標註的預設」；只顯示相關屬性，保留穩定欄位位置 | 使用者能預測修改影響；選取物件的樣式變更不被誤認為全域設定 |
| M3 可見的完成與取消 | 裁切時顯示「套用裁切／取消」；文字輸入提示如何完成；選取物件後有可見的操作選單入口 | 不必事先背 Enter、Ctrl+Enter 或猜測右鍵位置；原快捷鍵仍可使用 |
| M4 一致的可讀性與版面 | 編輯器、設定、確認對話框採一致文字層級、控制項間距、焦點與錯誤辨識；設定內容超出時可到達 | 文字放大、可行的 DPI／視窗組合下，所有必要動作與文字仍可取得；不以縮小字體硬塞 |
| M5 鍵盤與可存取名稱 | 新入口能透過 Tab／存取鍵開啟；焦點清楚，控制項名稱與目前物件狀態可被理解 | 以實際鍵盤與 Narrator 驗證這次涉及的流程，不把自動化名稱存在當作完整通過 |

字級先以 Windows 文字設定與繁中閱讀情境為依據；若需要比較原型，可試 14～16 DIP 的主要控制文字，**這是設計起點，不是標準規定，也不是既有介面已不合格的結論**。增加留白時應觀察畫布可用面積，不採全面等比例放大。

### 6.2 明確不包含

- 新增遮蔽、OCR、長截圖、圖片釘選或其他新工具。
- O03 的各目的地版本追蹤、重試流程與複製後返回動作；M1 只改善既有輸出的可發現性。
- O04 的成品文字底色、換行、樣式模板；M2 只釐清既有屬性操作。
- 自動存圖、圖片歷史、雲端同步、帳號、遙測與行為上傳。
- 全面重新定義品牌、強制深色主題、動畫改版或純技術重構。
- 完整無滑鼠框選、所有標註的鍵盤幾何編輯；這需要 O09 等後續設計。M5 通過不代表整個產品已完全無障礙。
- 改變原始圖片像素、100% 縮放定義、PNG／DIB 內容一致性或取消未匯出保護。

## 7. Success Metrics 與價值驗證

### 7.1 指標：先建立基準，再比較

以下數字都是**建議目標**，Repository 沒有現況使用者指標。功能測試通過不能替代這些指標。

| 指標 | 定義與收集方式 | MVP 建議門檻 |
|---|---|---|
| 無協助任務完成率 | 在指定輸入與成品要求下，不經研究員提示而完成四種任務；完成後以圖像與設定狀態確認 | 至少 90%；同時列出各任務與新手／熟手結果，不能只報平均 |
| 操作耗時 | 從看見任務到完成正確成品，包含尋找及修正；比較同一人的等價任務 | 中位數較現版下降至少 25%；同時報失敗數、最慢案例與原始分布 |
| 誤操作及修正次數 | 點錯工具、改錯作用對象、找不到套用／取消、因誤操作而復原 | 相對基準減少至少 50%；若基準接近零，不以此百分比作通過理由 |
| 作用對象辨識 | 操作前詢問「這次改色會影響誰？」；答案須符合實際行為 | 至少 90% 正確，且不能靠研究員解釋後才答對 |
| 可讀性與專業感 | 每個版本任務後以 1～7 分評估「容易閱讀」「層級清楚」「願意日常使用」，加一句原因 | 中位數至少提高 1 分，且客觀任務指標沒有退步 |
| 小視窗與文字放大可用性 | 在可行的 720×420、960×640、1280×860 DIP 工作區，以及 100%、125%、175%、200% DPI 的代表組合中驗證；另測 Windows 文字放大 | 必要操作可到達、標籤可辨認、不互相覆蓋；若工作區小於最低尺寸，另列限制，不偽稱通過 |
| 鍵盤與輔助操作 | 不使用滑鼠尋找工具、切換屬性、開啟物件操作選單、完成／取消裁切；檢查名稱與焦點宣告 | MVP 納入的任務全部可完成；完整框選仍另列未涵蓋 |
| 熟手效率護欄 | 比較熟手常用快捷鍵及指標操作任務 | 中位數不得變慢超過 10%，快捷鍵、IME 與取消行為不能退步 |
| 正確性與隱私護欄 | 等價編輯的輸出像素、裁切範圍、復原、文件切換與失敗保留 | 既有相關驗證維持通過；沒有新增螢幕內容持久化或網路傳送 |

可讀性量測可參考 WCAG2ICT 的非網頁軟體解讀：一般文字對比以 4.5:1、符合大字條件的文字以 3:1 作檢查起點，必要的非文字辨識採對應的 3:1 指引，並逐項確認適用範圍與例外。它是說明性指引，不是本報告對產品的合規認證，也不能拿停用控制項的灰字直接宣告違規。[W3C WCAG2ICT](https://www.w3.org/TR/wcag2ict/)

控制項名稱、狀態事件、系統顯示設定與可見焦點，參考 Microsoft 的 Windows 可存取性實務；自繪畫布必須以實際輔助科技驗證，不能只依賴標準控制項已有的支援。[Microsoft Accessibility best practices](https://learn.microsoft.com/en-us/windows/win32/winauto/accessibility-best-practices)

### 7.2 如何驗證價值

1. **先觀察現版**：邀請約 12 位符合主要情境的人，包含 6 位初次使用者與 6 位熟手；另確保有鍵盤／文字放大／輔助科技需求的參與者。這是形成性研究規模，不足以推論整體市場或宣稱統計顯著。
2. **使用同等但不同內容的任務**：以無敏感資訊的範例圖做現版與原型比較，交錯版本順序與素材，避免同一張圖練熟造成假改善。計時、錯誤、求助與成品正確性一起記錄，失敗任務不得從結果剔除。
3. **驗證具體誤解**：要求「只把這個箭頭改藍，不改下一個新箭頭的預設」「裁切後取消」「不用查文件重新編輯文字」，觀察是否依賴猜測或提示。另讓使用者找出複製與另存，但不把 O03 尚未做的版本狀態算入 M1 效益。
4. **加入閱讀與工作區條件**：使用實際大小顯示，不用縮小截圖評論字級。涵蓋繁中長標籤、放大的文字、高對比設定與較小視窗；設定、確認對話框一起檢查。
5. **短期成功後再看持續使用**：以 2～4 週自願試用日誌，記錄每週有截圖需求的天數、選用 ScreenshotApp 的天數、改用其他工具的原因。沒有需求的日子不當成流失。只收使用者同意的匿名任務摘要，不記錄螢幕內容，不新增預設遙測。
6. **做出投資判斷**：完成率、時間或誤操作至少有明確改善，且熟手與正確性護欄通過，才擴大實作。只有「看起來更漂亮」而沒有使用結果改善時，保留有效的字級／層級調整，停止大範圍重新設計。

後續 O02 應測敏感區遮蔽成功與跨工具切換；O03 應測版本辨識、失敗恢復與錯貼；O04 應讓成品接收者辨讀標註；O05 應從啟動算到第一次貼出成品。每個項目使用自己的成功指標，不能把 O01 的結果外推為所有候選都有價值。
