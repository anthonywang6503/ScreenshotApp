# ADR-0016：未匯出變更保護流程

- **狀態**：Accepted
- **日期**：2026-10-18

## 背景

同時只開啟一份文件。若內容自最後一次成功匯出後曾修改，使用者要求新截圖、開啟其他圖片、關閉或結束時，必須提供複製、儲存、捨棄或取消等明確選擇，不得無聲丟棄資料。流程規則另外寫到「新截圖可能覆蓋未匯出內容時，在開始新截圖前先處理確認」；取消新截圖要恢復原文件；複製或另存後留在編輯狀態；關閉編輯視窗只回到常駐。

兩段文字對「從未匯出、也沒有任何修改的截圖」結論不同：前者以「曾修改」為條件，後者寫「未匯出內容」。本專案的文件優先序是明確需求先於流程描述。

Phase 3 的編輯歷史只保存命令，沒有版本；新截圖直接取代文件，關閉編輯器直接捨棄。系統匣「結束」呼叫 `Application.Shutdown`，關閉視窗時不能取消。

## 決策

1. **「未匯出」的定義**：編輯歷史為每個狀態編上版本。每執行一個新命令產生一個新版本；復原與重做回到相鄰狀態的版本。文件記錄最後一次成功匯出時的版本，目前版本與它不同即為未匯出；修改後再復原回匯出時的狀態，視為沒有未匯出的變更。歷史超過容量捨棄最舊的一筆時，最底層狀態的版本改為被捨棄那筆命令執行後的版本。
2. **剛截取或剛開啟的圖片沒有未匯出的變更**：依明確需求以「自最後一次成功匯出後曾修改」為條件。結果是未加任何修改的截圖在新截圖、開啟圖片、關閉編輯器或結束時不詢問；最常見的「截錯了重截一次」不會多一次確認。
3. **詢問時機**：
   - **新截圖**（快捷鍵、系統匣）：在隱藏視窗與擷取畫面之前詢問，選擇後才開始截圖，對話框不會被截入。之後取消新截圖，仍恢復原文件。
   - **開啟圖片**（系統匣、編輯器按鈕、`Ctrl+O`）：先詢問，再顯示開啟檔案對話框；之後取消開檔或載入失敗，原文件不變。
   - **關閉編輯器**：攔截關閉，詢問後才關閉。
   - **系統匣「結束」**：先帶出編輯器並詢問，確定後才結束程式；結束過程中不再詢問。
   - **登出或關機**：有未匯出的變更時拒絕結束工作階段，帶出編輯器並詢問；使用者處理後需重新登出或關機。
4. **選項**：
   - **複製**：複製成功才繼續；失敗則顯示原因並中止原本的操作。
   - **儲存**：另存成功才繼續；取消存檔對話框或寫入失敗都中止原本的操作。
   - **捨棄**：直接繼續。
   - **取消**：中止原本的操作，文件不變。`Esc` 或關閉對話框等同取消，沒有預設為破壞性動作的按鈕。
5. **詢問前先完成進行中的文字輸入**（與複製、儲存相同），再判斷是否有未匯出的變更。
6. **不重疊**：對話框開啟期間，新的截圖、開啟圖片與結束要求一律忽略。
7. **對話框**為 WPF 視窗：文字取自資源檔、按鈕有存取鍵與工具提示。

## 考慮過的替代方案

- **以操作次數判斷是否修改**：修改後再復原回原狀仍會詢問。
- **從未匯出的文件一律詢問**：每次重截都要多一次確認；若使用者希望未修改的截圖也要詢問，只需改變新文件的初始匯出版本。
- **Windows TaskDialog（Windows Forms）**：需要啟用 Common Controls 6 的視覺樣式，並擴大 Windows Forms 的使用範圍。
- **自動暫存未匯出的內容**：違反「除使用者明確儲存外不得持久化螢幕內容」。
- **先顯示開啟檔案對話框再詢問**：可少問一次（使用者取消開檔時），但與一般桌面程式「先處理目前文件」的順序不同。

## 影響

- 未修改的截圖可以直接關閉或被新截圖取代；使用者若需要不同的行為可在控制點提出。
- 系統匣「結束」與登出、關機都可能因詢問而暫停；登出、關機的情境需實際登出才能驗證。
- 編輯歷史與文件模型多一個版本欄位；版本判斷以單元測試驗證，各詢問路徑以煙霧腳本驗證。
