# ADR-0003：單一執行個體——具名 Mutex + EventWaitHandle

- **狀態**：Accepted
- **日期**：2026-10-18

## 背景

規格要求不得產生兩組系統匣圖示或重複註冊快捷鍵；再次啟動時須通知既有執行個體，顯示其設定或編輯視窗。v1.0 沒有命令列參數，第二個執行個體不需要傳遞任何資料，只需要「喚醒」第一個執行個體。

Windows 的前景鎖定規則會阻止背景處理程序把自己的視窗帶到前景；若第一個執行個體直接呼叫 `Window.Activate()`，通常只會讓工作列按鈕閃爍。

## 決策

1. 以具名 `Mutex`（`Local\` 命名空間，名稱含固定 GUID）判斷是否為第一個執行個體。`Local\` 範圍為目前登入工作階段，不同 Windows 使用者各自擁有獨立執行個體。
2. 第一個執行個體建立具名 `EventWaitHandle`（AutoReset），以 `ThreadPool.RegisterWaitForSingleObject` 等待訊號，收到後透過 UI `Dispatcher` 顯示設定視窗（有開啟中的編輯文件時改為顯示編輯視窗）。
3. 第二個執行個體在任何系統匣、快捷鍵或視窗建立之前：
   1. 呼叫 `AllowSetForegroundWindow(ASFW_ANY)`，把自己（剛由使用者啟動、擁有前景權限）的前景權限讓出；
   2. 開啟（必要時建立）同名事件並 `Set()`；
   3. 以結束代碼 0 立即結束。
4. 兩個核心物件皆在應用程式結束時釋放。

## 考慮過的替代方案

- **具名管道或 `WM_COPYDATA`**：能傳遞資料，但本版沒有資料需要傳遞，徒增複雜度；`FindWindow` 尋找視窗也較脆弱。
- **`Microsoft.VisualBasic` 的單一執行個體支援**：以 Windows Forms 應用程式模型為中心，不適合 WPF 啟動流程。

## 影響

- 實作小而可靠；兩個處理程序幾乎同時啟動時，事件可能在第一個執行個體開始等待前就被釋放而遺失一次喚醒，這只影響「顯示視窗」而不影響單一執行個體保證。
- `ASFW_ANY` 只允許在目前輸入事件期間由任意處理程序取得前景，影響範圍短暫。
- 既有執行個體若以系統管理員身分執行，一般權限的新執行個體無法開啟其具名物件；此時同樣視為已有執行個體而直接結束（無法喚醒它顯示視窗），不會產生第二組系統匣圖示。
