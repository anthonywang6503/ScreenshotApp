# ADR-0008：覆蓋層定位與輸入座標——HwndSource 直接建立於顯示器實體邊界、取自事件本身的實體像素

- **狀態**：Accepted
- **日期**：2026-10-18

## 背景

每個顯示器都需要一個可操作的選取覆蓋層，且必須精確貼合該顯示器：多螢幕可能有負的桌面座標、不同解析度與不同縮放比例。WPF `Window` 以 DIP 配置位置，視窗若先在某個顯示器建立、再移到 DPI 不同的顯示器，Windows 會送出 `WM_DPICHANGED`。從 WPF 原始碼確認：`HwndTarget` 收到該訊息時讀取建議矩形（依 DPI 比例縮放過的尺寸）並以它重設視窗大小；若在 `HwndSource.DpiChanged` 事件中標記已處理，WPF 連畫面縮放都不會更新。換言之，「先建立再移動」的做法必須介入 WPF 的 DPI 處理才能得到精確邊界。

開發機只有一個顯示器（3456×2160、175%），任何「跨 DPI 移動視窗」的程式路徑在本機永遠不會被執行到，無法以實機驗證。

## 決策

1. **出生即在目標顯示器**：每個顯示器一個覆蓋層，以 `HwndSource` 直接在該顯示器的實體像素邊界建立（`WS_POPUP`；延伸樣式 `WS_EX_TOPMOST | WS_EX_TOOLWINDOW`，不出現在工作列與 Alt+Tab）。Per-Monitor V2 下 WPF 以 `GetDpiForWindow` 取得 HWND 的初始 DPI，因此覆蓋層一建立就是該顯示器的 DPI，沒有跨 DPI 移動的路徑。
2. **顯示**：覆蓋層內容的背景為該顯示器快照，`Stretch=Fill` 並使用最近鄰取樣；用戶區的 DIP 尺寸乘上 DPI 縮放等於實體像素，快照像素與螢幕像素一對一。暗化遮罩、選取框與尺寸標籤疊在快照上。
3. **輸入座標**：滑鼠位置取自每個滑鼠事件本身：WPF 以覆蓋層的 DPI 把該訊息中的實體像素換成 DIP，再經 `CoordinateMapper` 以同一比例換回顯示器本地實體像素並加上顯示器原點（整數像素往返誤差為 0，已由測試涵蓋所有常見縮放）。不在事件處理當下讀取 `GetCursorPos`：UI 執行緒忙碌而延後處理按下或放開事件時，游標可能已經移開，起點或終點會偏移（煙霧驗證實際量到）。`GetCursorPos` 只用來決定顯示時由哪個覆蓋層取得焦點。按下滑鼠的位置決定起始顯示器，並以 `Mouse.Capture` 鎖定在該覆蓋層；游標移到其他顯示器時事件仍送到起始覆蓋層，座標夾取在起始顯示器內。
4. **選取範圍**：包含起點與終點兩個像素，即 `[min, max + 1)`，因此可以選到顯示器最後一行與最後一列。在起點像素放開代表沒有拖曳，視為零尺寸：不產生任何結果，覆蓋層維持在選取狀態，使用者可重新拖曳或取消。
5. **換算集中**：選取框、遮罩與尺寸標籤的 DIP 位置只經 `CoordinateMapper` 由顯示器本地實體像素換算；尺寸標籤顯示實體像素寬高。選取框是選取範圍外側一圈整數像素寬的環（外矩形減內矩形），遮罩與選取框都不做邊緣平滑，邊界剛好落在像素格線上，選到的像素不會被外框蓋住或被半暗化。
6. **鍵盤與取消**：覆蓋層顯示後，把游標所在顯示器的覆蓋層帶到前景並取得鍵盤焦點；`Esc` 或在任何覆蓋層按滑鼠右鍵即取消。
7. **顯示設定變更**：覆蓋層的訊息 hook 收到 `WM_DISPLAYCHANGE`（解析度、排列、插拔顯示器）或 `WM_DPICHANGED` 時取消選取並提示，因為快照與目前的顯示器配置已不一致。覆蓋層出生即在最終位置且從不移動，收到 `WM_DPICHANGED` 只可能是該顯示器的縮放比例被變更；此時直接標記為已處理，不讓 WPF 依建議矩形改變覆蓋層大小。hook 隨覆蓋層關閉而解除，不使用靜態的 `SystemEvents` 訂閱。

## 考慮過的替代方案

- **WPF `Window` + `SourceInitialized` 後 `SetWindowPos`**：跨 DPI 移動時需在自己的 hook 中改寫 `WM_DPICHANGED` 的建議矩形（自訂 hook 會先於 WPF 收到訊息，技術上可行），但這條路徑在本機無法執行，正確性只能靠推論。
- **單一視窗覆蓋整個虛擬桌面**：一個視窗只能有一個 DPI，跨越不同縮放的顯示器時其他顯示器上的畫面會被縮放而模糊或錯位。
- **在事件處理當下讀取 `GetCursorPos`**：最初的做法，看似直接取得整數實體像素，但讀到的是處理當下而非事件發生時的位置；煙霧驗證中，覆蓋層剛顯示、UI 執行緒仍忙碌時開始拖曳，選取範圍只剩拖曳路徑的一部分。
- **`GetMessagePos`**：可取得訊息發生時的位置，但 WPF 由觸控等來源轉換而來的滑鼠事件不一定對應目前的視窗訊息。

## 影響

- 單一顯示器上的貼合與像素正確性由 Agent 實機煙霧驗證（覆蓋層邊界、與已知圖樣逐像素比對）；混合 DPI、負座標與上下排列依賴使用者實機驗收（雙螢幕混合 DPI），在回報前標示「尚未驗證」。
- 覆蓋層不是 WPF `Window`，不在 `Application.Current.Windows` 中；生命週期由選取控制器管理，「隱藏自家視窗」也不會誤動到覆蓋層。
