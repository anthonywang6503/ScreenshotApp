# ADR-0010：文件模型與命令模式（Undo／Redo）

- **狀態**：Accepted
- **日期**：2026-10-18

## 背景

編輯器必須以「原始 Bitmap + 向量標註 + 非破壞性裁切 + Command Pattern」實作：標註可選取、移動、調整尺寸或端點、修改樣式、刪除與調整前後層順序；文字與步驟編號可修改；裁切可重複調整；全部可 Undo／Redo，一次連續拖曳只記錄一筆，最多保留 100 筆，且不得儲存每一步的完整 Bitmap。原始 Bitmap 在編輯工作階段中不得被覆寫，所有座標以原始圖片像素為基準，裁切時不改寫標註座標。

## 決策

1. **`ImageDocument`** 持有凍結的原始 Bitmap、原始整數像素寬高、`CropRect`（非空、位於原圖內的 `PixelRect`）、按層序排列的標註清單（索引即前後層順序，0 為最底層）與編輯歷史 `UndoRedoStack`。下一個步驟編號為「現有最大編號 + 1」，不另存計數器，刪除與復原都不需要額外處理。選取、預覽、目前工具等畫面狀態不屬於文件。
2. **標註為不可變 record**，以 `Guid` 識別：
   - `BoxAnnotation`（矩形範圍 + 線寬）→ `RectangleAnnotation`、`EllipseAnnotation`
   - `SegmentAnnotation`（起點、終點 + 線寬）→ `LineAnnotation`、`ArrowAnnotation`
   - `TextAnnotation`（起點、文字、字型、字級）
   - `StepNumberAnnotation`（中心、半徑、編號）

   每個標註都有顏色。幾何一律為**整數圖片像素**：矩形範圍採半開區間，拖曳建立時與區域選取相同，包含起點與終點兩個像素；線段端點與編號中心指「該像素」，繪製時通過像素中心；文字起點為該像素的左上角。修改標註就是產生一份帶相同 Id 的新 record。
3. **命令只有五類**：新增、刪除、替換（移動、調整大小、樣式、文字、編號都是「把同一個標註換成新值」）、設定裁切、調整層序。命令以 Id 找標註，`Execute` 與 `Undo` 都是「設為某值」，重複執行無害。
4. **文件只經由命令修改**：拖曳期間由編輯工作階段保存預覽並即時繪製，放開滑鼠時才執行一筆命令；取消拖曳只需丟棄預覽。文件的狀態因此永遠等於歷史紀錄的結果。
5. **`UndoRedoStack`**：執行新命令時清除 Redo；超過 100 筆時捨棄最舊的一筆。歷史中只有標註 record 與矩形，沒有任何 Bitmap。
6. 「最後一次成功匯出後是否修改」的版本追蹤，在使用它的未匯出變更保護流程實作時一併加入。（已實作：`UndoRedoStack` 的狀態版本與 `ImageDocument.ExportedVersion`／`IsDirty`，見 ADR-0016。）

## 考慮過的替代方案

- **可變標註 + 每種屬性一個命令類別**：每個命令都要記錄舊值並逐一還原，類別數量多且容易漏掉欄位；不可變 record 讓 Undo 只需保存前後兩個值。
- **每一步保存整份文件快照**：實作簡單，但規格禁止保存每一步的完整 Bitmap；只保存標註清單雖然可行，仍比命令浪費記憶體，也無法表達「一次拖曳一筆」以外的細節。
- **以索引而非 Id 找標註**：層序調整與刪除會改變索引，Undo／Redo 的順序一旦交錯就會改到錯的物件。
- **浮點座標**：可表達子像素位置，但輸出與測試無法精確比對；圖片像素是本程式的唯一真值。

## 影響

- 標註幾何、命令與歷史都是純邏輯，可完整單元測試（新增、移動、調整、樣式、刪除、層序、重疊選取、可逆性、一次拖曳一筆、上限）。
- 新截圖或開啟圖片時建立新的 `ImageDocument`，歷史隨之重置。
- 未匯出變更保護加入前，取代或關閉文件不會詢問，需在文件與控制點揭露。（未匯出變更保護加入後已會詢問。）
