# ADR-0002：座標系統——實體像素為唯一真值，集中於 CoordinateMapper

- **狀態**：Accepted
- **日期**：2026-10-18

## 背景

使用者可能有多顆不同解析度與縮放比例的顯示器，主螢幕左側或上方的顯示器具有負的桌面座標。WPF 以裝置無關像素（DIP，1/96 英吋）配置畫面，而截圖、裁切與輸出圖片都以實體像素為單位。若各模組自行換算 DPI，誤差與偏移會四處擴散；規格要求螢幕、裁切與圖片模型以實際像素為唯一真值，WPF DIP 只用於顯示與互動，且座標轉換必須集中管理。

## 決策

1. 處理程序宣告 **Per-Monitor V2 DPI Awareness**（`app.manifest`），讓 Win32 API 回傳未經虛擬化的實體像素座標，並讓每個視窗在其所在顯示器的 DPI 下繪製。
2. 定義四種座標空間，型別與命名明確區分：

   | 空間 | 原點 | 單位 | 用途 |
   |------|------|------|------|
   | `DesktopPhysicalPx` | 主螢幕左上角（可為負值） | 實體像素（整數） | 顯示器邊界、游標位置 |
   | `MonitorLocalPx` | 該顯示器左上角 | 實體像素（整數） | 選取結果、逐顯示器快照 |
   | `ImagePx` | 原始圖片左上角 | 圖片像素 | 文件模型：裁切、標註 |
   | `ViewDip` | 視窗用戶區左上角 | WPF DIP | 覆蓋層與編輯器畫布的顯示與滑鼠輸入 |

3. 截圖逐顯示器擷取，因此新截圖的 `ImagePx` 與該顯示器的 `MonitorLocalPx` 相同；開啟既有圖片時 `ImagePx` 即檔案像素。
4. 選取與裁切範圍使用整數 `PixelRect`（左上包含、右下不包含的半開區間）。
5. 所有空間之間的換算**只**存在於 `Capture/CoordinateMapper`（純函式，可單元測試）；其他模組不得自行乘除 DPI 比例。
6. 編輯器 100% 縮放定義為「1 圖片像素 = 1 實體像素」，因此畫布的 WPF 縮放倍率為 `zoom / dpiScale`（細節見後續畫布縮放 ADR）。

## 考慮過的替代方案

- **以 WPF DIP 為模型座標**：在 125%、150% 等非整數縮放下，DIP 與實體像素往返會產生小數誤差，輸出尺寸無法嚴格等於選取尺寸。
- **System DPI Aware**：Windows 會對非主螢幕 DPI 的視窗做點陣圖縮放，造成覆蓋層模糊與座標偏移。

## 影響

- DPI 數學集中、可測試；混合 DPI 與負座標以自動化測試（座標映射）涵蓋，往返誤差需 ≤ 1px。
- 覆蓋層與編輯器在顯示時仍需處理 WPF 的 DIP 配置，但只透過 `CoordinateMapper` 取得換算結果。
- 所有接觸座標的程式碼審查時需確認使用的是哪一種空間。
