# ADR-0009：應用程式狀態機與重入保護

- **狀態**：Accepted
- **日期**：2026-10-18（2026-10-18 修訂：編輯器加入後的狀態與轉換，見文末「修訂」）

## 背景

規格定義應用程式狀態為 Resident → Capturing → Selecting → Editing → Resident，並要求：截圖期間再次收到快捷鍵不得重入；取消選取時返回先前狀態（原本有編輯文件時須恢復文件與視窗）；擷取失敗或顯示設定在選取期間改變時，安全取消、顯示錯誤且不留下全螢幕遮罩。觸發截圖的來源有快捷鍵與系統匣選單，另外第二個執行個體的喚醒會要求顯示設定視窗。

## 決策

1. **`AppStateMachine`**：只在 UI 執行緒使用。目前狀態為 Resident、Capturing、Selecting；Editing 與其轉換（選取完成進入 Editing、取消時回到先前狀態、關閉編輯器回到 Resident）在編輯器加入時一併實作，不預先放入沒有使用者的狀態。
2. **轉換守衛**：只有 Resident 可以開始截圖。Capturing 與 Selecting 期間，快捷鍵、系統匣「開始截圖」與第二個執行個體的喚醒一律忽略。不合法的轉換代表程式錯誤，直接拋出例外，不靜默略過。
3. **`CaptureFlow`**：依序執行「開始截圖 → 隱藏自家視窗並等待合成器 → 快照 → 進入 Selecting → 等待選取 → 裁切」。完成、取消、擷取失敗、顯示設定變更與未預期例外等所有結束路徑，都在 `finally` 中恢復被隱藏的視窗、確保覆蓋層已關閉並回到 Resident。
4. **可測試的接縫**：隱藏視窗、快照與區域選取這三個平台步驟經 `ICaptureEnvironment` 注入；自動化測試以替身驗證步驟順序與每條路徑的回復，不需要建立系統匣圖示或全螢幕視窗。
5. **結果交付**：流程只回傳結果（完成時附裁切後的圖片、失敗時附原因），由 `AppController` 決定後續動作。在編輯器完成前，完成的截圖複製到剪貼簿並以通知告知尺寸；編輯器完成後改為開啟編輯器。
6. **系統匣來源**：選單的「開始截圖」延後到選單事件處理結束後才開始，選單先從畫面移除，再進入隱藏視窗與等待合成器的步驟。

## 考慮過的替代方案

- **單一布林旗標（例如「截圖中」）**：能擋住重入，但無法表達「返回先前狀態」，編輯器加入後會再出現第二、第三個旗標。
- **通用狀態機套件**：狀態與轉換數量很少，引入套件的成本高於收益，也違反不引用不必要框架的原則。

## 影響

- 重入保護與回復邏輯集中在 `AppStateMachine` 與 `CaptureFlow`，由單元測試涵蓋；實際的快捷鍵連按、取消與失敗情境另以實機煙霧驗證。
- 編輯器階段需擴充狀態機（Editing）與流程的完成路徑，並補上對應測試。

## 修訂（編輯器加入後的現況）

決策第 1、2、5 點記錄的是編輯器加入前的階段，現況如下：

1. 狀態機加入 `Editing`。`TryBeginCapture` 接受 Resident 或 Editing，並記住開始前的狀態；`EndCapture` 回到該狀態，因此取消新截圖時回到原本的編輯狀態，文件與視窗不變。`BeginEditing`／`EndEditing` 對應編輯視窗的開啟與關閉；已在編輯時 `BeginEditing` 代表以新文件取代目前的文件。
2. Capturing 與 Selecting 期間仍忽略新的截圖要求與第二個執行個體的喚醒（不顯示設定視窗）。此外 `AppController` 在詢問未匯出的變更、背景匯出或編輯視窗開著自己的模態對話框時，也忽略新的截圖、開啟圖片與結束要求（見 ADR-0016 的修訂）。
3. 完成的截圖改為開啟編輯器；第 5 點「複製到剪貼簿並通知」只存在於編輯器加入之前。
