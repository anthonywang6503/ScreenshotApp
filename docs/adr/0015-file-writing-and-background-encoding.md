# ADR-0015：檔案寫入與背景編碼——暫存檔後取代、凍結的圖片交給背景執行緒

- **狀態**：Accepted
- **日期**：2026-10-18

## 背景

另存 PNG 要提供存檔對話框，預設檔名為 `Screenshot_yyyyMMdd_HHmmss_fff.png`，初始位置為「圖片」資料夾或上次成功儲存的位置；同名檔案需確認覆寫，寫入失敗不得丟失圖片。開啟的既有圖片在未取得明確確認前不得覆寫來源檔案。除使用者明確儲存外，不得把螢幕內容寫入永久檔案。耗時的圖片編碼與檔案 I/O 不應長時間阻塞 UI 執行緒，跨執行緒傳遞圖片需遵守 WPF 的執行緒親和與 Freezable 限制。

Phase 3 的 `PngFileService.Save` 已是「先寫暫存檔、完整寫入後才取代目標」，但編碼與寫檔在 UI 執行緒進行，初始資料夾固定為「圖片」。

## 決策

1. **流程**：
   1. UI 執行緒：完成進行中的文字輸入，顯示存檔對話框，合成圖片（`RenderTargetBitmap`，結果凍結），記下合成當時的文件版本。
   2. 背景執行緒：以 `PngBitmapEncoder` 編碼凍結的圖片，寫入目標資料夾內的暫存檔，再以 `File.Move(..., overwrite: true)` 取代目標。
   3. 回到 UI 執行緒：成功時以合成當時的版本標記已匯出、記住資料夾、在狀態列提示；失敗時以繁體中文顯示原因，文件不變。
2. **暫存檔**：與目標同一資料夾、名稱為 `<檔名>.<GUID>.tmp`、以 `FileMode.CreateNew` 建立；任何失敗都刪除暫存檔。同一資料夾內的重新命名讓目標檔只在完整寫入後才被取代，中途失敗不會留下不完整的 PNG，也不會破壞同名的既有檔案。
3. **對話框**：`SaveFileDialog` 開啟覆寫確認，同名檔案由使用者在對話框中明確確認。預設檔名一律為 `Screenshot_yyyyMMdd_HHmmss_fff.png`；開啟的既有圖片也不以來源檔名為預設，避免誤覆寫來源。初始資料夾為上次成功儲存的資料夾（仍存在時），否則為「圖片」資料夾。
4. **上次儲存位置**只在儲存成功後寫入設定檔；設定檔寫入失敗時在狀態列提示，不影響已完成的儲存。
5. **不重疊**：複製或儲存進行中，兩個命令都停用（與剪貼簿共用同一個狀態）。
6. **編碼共用**：剪貼簿的 PNG 格式與檔案使用同一個編碼函式，兩者的位元組相同。

## 考慮過的替代方案

- **在 UI 執行緒同步編碼（Phase 3 現況）**：4K 圖片的編碼需要數百毫秒，期間視窗沒有回應。
- **直接寫入目標檔**：中途失敗會留下不完整的檔案，並破壞同名的既有檔案。
- **`File.Replace`**：要求目標已存在，並附帶備份與屬性處理，語意比需要的複雜。
- **在背景執行緒合成**：`RenderTargetBitmap` 與標註繪製需要有 Dispatcher 的 STA 執行緒；合成只需數十毫秒，耗時的是編碼與寫檔，沒有必要另建 STA 執行緒。

## 影響

- 編碼期間可以繼續編輯；儲存的是按下儲存當時的內容，之後的修改會讓文件再次成為未匯出狀態。
- 編碼期間關閉編輯器，寫檔仍會完成，但結果不再顯示。
- 唯讀資料夾、資料夾不存在、目標為唯讀檔等失敗情境以單元測試驗證，實機另以煙霧腳本確認失敗後文件仍在。
